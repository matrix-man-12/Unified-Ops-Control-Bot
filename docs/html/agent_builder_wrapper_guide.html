Agent Builder LLM Wrapper Specification Guide

This developer guide provides comprehensive technical specifications for building an OpenAI-compatible adapter/wrapper around your proprietary corporate Agent Builder LLM API. Exposing an OpenAI-compatible chat completion endpoint enables seamless, plug-and-play integration with the Unified Portal Control Agent workspace.

1. System Context & Wrapper Routing Architecture

Currently, the portal orchestrator instantiates LLM connectors dynamically using LangChain components. As defined in the codebase inside planner.py, selecting the Agent Builder API in the workspace triggers a standard LangChain ChatOpenAI call directed to the corporate endpoints:

elif prov == "agent_builder":
    return ChatOpenAI(
        model=settings.AGENT_BUILDER_MODEL,
        openai_api_key=settings.AGENT_BUILDER_API_KEY,
        openai_api_base=settings.AGENT_BUILDER_BASE_URL,
        temperature=0.0
    )

Because the ChatOpenAI client automatically appends /chat/completions to the base url parameter, your internal wrapper proxy must listen on the exact REST route path: http://<adapter-host>:<port>/chat/completions.

Architectural Flow: 
+--------------------------------+
|  Unified Portal Agent Backend  |
+--------------------------------+
                |
                | [LangChain ChatOpenAI requests]
                | POST http://adapter-host:port/chat/completions
                v
+--------------------------------+
|   Corporate Wrapper Adapter    | <--- Converts OpenAI spec models
+--------------------------------+
                |
                | [Proprietary schema conversions]
                | POST https://corporate.internal.llm/api/v1/generate
                v
+--------------------------------+
|     Corporate LLM Service      |
+--------------------------------+

2. OpenAI Request & Response Payload Contract

Your wrapper proxy must consume standard OpenAI payloads (which carry a structured array of system and user messages) and translate them into your proprietary corporate LLM format, which expects a single input key named input_value.

A. Proprietary Corporate API Request Schema (JSON)

The internal Agent Builder API takes a simple JSON request containing a single key input_value, carrying the collated instruction prompt string:

{
  "input_value": "[SYSTEM]: System prompt instruction directives...\n[USER]: The user query and Swagger specifications context..."
}

B. Wrapper Proxy Request Contract (JSON)

The wrapper adapter itself exposes a standard OpenAI POST endpoint at /chat/completions:

{
  "model": "your-corporate-model-id",
  "messages": [
    {
      "role": "system",
      "content": "You are an expert planner..."
    },
    {
      "role": "user",
      "content": "Create 5 users..."
    }
  ],
  "temperature": 0.0,
  "max_tokens": 4096
}

B. Target API Response Contract (JSON)

Your adapter must return the choices text wrapped in a standard OpenAI choice block:

{
  "id": "chatcmpl-uniqueId12345",
  "object": "chat.completion",
  "created": 178229840,
  "model": "your-corporate-model-id",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "The generated string content (Raw JSON plan array or YAML skill)..."
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 1200,
    "completion_tokens": 850,
    "total_tokens": 2050
  }
}

3. Required LLM Features & Cognitive Capabilities

To support the agent's advanced operational workflows, your internal LLM must satisfy three core features:

1. Token Context Window: Min 16k (Ideally 32k+)

The planner node bundles massive datasets into a single prompt. Your internal LLM context window must be large enough to hold:

  • OpenAPI Swagger Documentations: Containing routing paths, HTTP method rules, required parameters, and JSON payloads.
  • Pre-defined Project Skills Context: A listing of currently registered YAML templates.
  • Full Conversational history: Maintaining warm thread context.

2. High-Fidelity JSON Schema Adherence (Planner Node)

The Dynamic Planner node requires precise structure to feed the steppers UI checklist. The LLM must generate a syntax-perfect, un-truncated JSON array block wrapped in markdown fences:

[
  {
    "step": 1,
    "id": "gather_details",
    "description": "Collect corporate email and username",
    "action_type": "collect_input",
    "tool_name": "create_user",
    "path": "/users",
    "method": "post",
    "param_mappings": [
      { "name": "email", "in": "body" }
    ],
    "inputs": {
      "email": "{{email}}"
    },
    "requires_approval": false,
    "input_fields": [
      {
        "name": "email",
        "type": "string",
        "required": true,
        "description": "User corporate email"
      }
    ]
  }
]

3. Syntax-Perfect YAML Generation (Skill Generator Node)

Under the "Skill Studio" view, developers can prompt the agent to draft custom skills automatically. Your LLM must output valid declarative YAML matching our parser parameters, supporting double curly-brace bindings ({{variable_name}}) and safety metrics.

4. Reference Implementation: Python & FastAPI Wrapper Adapter

If you need to stand up a lightweight proxy adapter on your internal corporate network, you can run this FastAPI script. It listens for incoming standard OpenAI calls, translates payloads to your proprietary endpoints, and returns standard chat structures:

import os
import httpx
from fastapi import FastAPI, Header, HTTPException
from pydantic import BaseModel
from typing import List, Dict, Any, Optional

app = FastAPI(title="Corporate Agent Builder LLM Wrapper Proxy")

CORPORATE_LLM_API_URL = os.getenv("CORPORATE_LLM_API_URL", "https://api.internal.corp/llm/v1/generate")

class OpenAIMessage(BaseModel):
    role: str
    content: str

class OpenAICompletionRequest(BaseModel):
    model: str
    messages: List[OpenAIMessage]
    temperature: Optional[float] = 0.0
    max_tokens: Optional[int] = 4096

@app.post("/chat/completions")
async def chat_completions(
    request: OpenAICompletionRequest,
    authorization: Optional[str] = Header(None)
):
    if not authorization:
        raise HTTPException(status_code=401, detail="Missing Authorization headers.")
    
    # Translate messages list into a prompt format suited for corporate LLMs
    combined_prompt = ""
    system_instruction = ""
    for msg in request.messages:
        if msg.role == "system":
            system_instruction = msg.content
        else:
            combined_prompt += f"\n[{msg.role.upper()}]: {msg.content}"

    # Collate system instructions and user chat loops into a single input_value string
    collated_prompt = f"[SYSTEM]: {system_instruction}\n{combined_prompt}"

    corporate_payload = {
        "input_value": collated_prompt
    }

    corporate_headers = {
        "X-Corp-Auth": authorization.replace("Bearer ", ""),
        "Content-Type": "application/json"
    }

    async with httpx.AsyncClient() as client:
        corp_res = await client.post(
            CORPORATE_LLM_API_URL,
            json=corporate_payload,
            headers=corporate_headers,
            timeout=60.0
        )
        corp_data = corp_res.json()

    # Map corporate output keys back to OpenAI models (e.g. output_value or generation_text)
    generated_text = corp_data.get("output_value") or corp_data.get("generation_text", "") or str(corp_data)
    
    return {
        "id": "chatcmpl-corp-" + os.urandom(8).hex(),
        "object": "chat.completion",
        "created": 178229840,
        "model": request.model,
        "choices": [
            {
                "index": 0,
                "message": {
                    "role": "assistant",
                    "content": generated_text
                },
                "finish_reason": "stop"
            }
        ],
        "usage": {
            "prompt_tokens": 1000,
            "completion_tokens": 800,
            "total_tokens": 1800
        }
    }
